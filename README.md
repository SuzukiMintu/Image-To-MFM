# Image-to-MFM
- 画像をMisskeyのMFMアートに変換するツールです。ブラウザーで動くJavaScript版と、既存のPython版があります。

## Web版

`web/` がそのまま公開できる静的サイトです。変換サーバー、外部ライブラリ、ビルド作業は不要です。

1. 画像ファイルを選択、またはドロップします。「Misskey.ioの絵文字で試す」から、サーバーに既存の絵文字でも試せます。
2. サイズ・色数・色形式・背景などを設定して「MFMに変換」を押します。
3. 元画像、変換後の色、MFMの表示イメージを確認して、コピーまたは `.txt` で保存します。
4. 「Misskeyの絵文字から読み込む」を開くと、サーバーURLと絵文字名（`aichan` / `:aichan:`）から画像を取得できます。
5. GIFを読み込むと「GIFの全コマを変換」が自動で選ばれます。1コマのサイズ・色数・表示時間を指定して変換し、再生プレビュー、各コマの色とMFMを確認できます。「静止画として変換」で従来の変換にも戻れます。「GIF絵文字で試す」はMisskey.ioの `petthex_meowsurprised` を取得します。

### ローカルで試す

Node.js 22以降を用意して、プロジェクトのフォルダーで実行します。

```console
node tools/serve.mjs
```

ブラウザーで `http://127.0.0.1:4173` を開きます。終了は Ctrl+C。`index.html` の直接起動ではなく、HTTPサーバーで開いてください。ブラウザーのES ModulesとWeb Workerを利用しています。

### GitHub Pagesで公開

1. このフォルダーをGitHubリポジトリに登録します。
2. GitHubの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にします。
3. `main` ブランチへ変更を反映すると、`.github/workflows/pages.yml` がテスト後に `web/` だけを公開します。別のブランチを使用する場合はworkflowの `branches` を変更してください。
4. 公開URLで絵文字の取得・変換、画像入力、コピー、保存を確認します。

公開先にはPythonファイル、作業用画像、開発用サーバーは含まれません。例示用の画像も同梱しません。「Misskey.ioの絵文字で試す」はクリック時に `https://misskey.io` の `ai_embarrassed_misskeyio` を通常の絵文字取得機能で読み込みます。取得できない場合はエラーを表示します。

### 設定と最適化

- サイズ・色数にツール独自の最大値はありません。静止画の各辺256px超／16,384画素超、GIFの各辺24px超、64色超などは生成前に警告を表示します。「設定に戻る」で生成せず中止し、「生成する」で続行します。GIFの多コマ・展開容量や大きな入力ファイルも警告対象です。警告の基準は入力を拒否する上限ではありません。
- GIFでも同じ横幅・縦幅・色数・色形式・背景と不透明度・減色の範囲・平滑化・刻み幅・似た色の統合・縦スケール・ピクセル文字・bg/fg・最適化・文字数上限・縮小設定を使えます。文字数上限は切り替え構文を含むGIF全体の文字数です。全コマを同じサイズで探索し、元サイズで収まらない場合だけ全コマを同じ比率で縮小します。収まらない場合は未達を明示します。
- GIFは色指定を行内に閉じる最適化を使い、コマの配置を保持します。入れ子は切り替え構文を含めてMisskeyの20段以内に収めるため、色指定には設定値以下の最大5段を使用し、実際の値を表示します。1コマ目も切り替えるため、透過やfg設定で前のコマが残りません。
- 「縦方向のスケール」は静止画・GIFの共通設定で、初期値は0.7です。GIFでも全コマに同じ値を適用します。コマを重ねる配置間隔には未変形の高さを使い、再生位置を維持します。
- 横幅または縦幅を0にすると元画像の縦横比を保ちます。両方0なら元のサイズです。変換後の各辺256・合計16,384ピクセルの固定制限は解除しました。実際に処理できるサイズはブラウザーと端末の容量によります。
- 「文字数の上限」は0で自動調整なしです。正の値を指定すると、指定サイズで最適化と減色候補の比較を行います。行ごと／画像全体の減色を試し、上限内では元の色との誤差が小さい候補を採用します。色形式や背景設定は保持します。
- 同じサイズで収まらない場合、「収まらない場合は画像を小さくする」がオンなら縦横比を保って約10%ずつ縮小します。各サイズの画像は毎回元画像から作り直します。画素数だけで文字数上限を超えるサイズでは、無駄な減色を省いて縮小します。
- 縮小をオフにした場合は指定サイズを保持します。1×1まで縮小しても収まらない場合も含め、上限を達成できなかったことを明示し、試した候補のうち短い結果を表示します。最終サイズ・文字数・採用した減色設定も表示します。
- 自動調整中は色配置を保つ最適化を常に有効にします。探索は有限の減色候補を比較する方式であり、最短・最高画質を保証するものではありません。透明度を削って文字数を合わせることはしません。
- 色数0でK-meansによる減色を無効化します。詳細設定で、行ごと／画像全体の減色、横方向の平滑化、刻み幅、似た色の統合を変更できます。
- 6桁RGBは色を保持、3桁RGB／4桁RGBAは最も近い短い色コードに丸めます。RGB形式では指定した背景色に合成して不透明にします。
- 「色味を変えずにMFMを短くする」は、減色・色コード化した後の色配置を保ったまま、行内の色指定と短いコードを再利用します。静止画では、不透明な行全体を囲む共通の土台色も候補にします。土台色は必ず行頭で開き行末で閉じ、上書きする色は各行で閉じます。透明・半透明を含む行には土台色を使わず、色が重ならないようにします。
- 最適化は候補を限定した探索です。土台色は色の連続区間への出現頻度が高い最大8色を候補にし、行のまとまりごとに実際の文字数で比較します。行単位の最適化・通常出力も比較し、短いものを採用します。必ず最短になるわけではありません。GIFでは引き続き行内限定です。
- 「最適化前」は**同じ設定で生成したWeb版の行単位出力**です。既存Python版の出力や、違う減色設定との比較ではありません。
- リサイズと変換・自動調整はWeb Workerで実行し、進捗を表示します。「処理を中止」または設定変更で処理を中止できます。再変換してからコピーしてください。
- 大きい出力の色プレビューは長辺512ピクセルまでの縮小表示とし、50,000文字を超えるMFMの表示イメージは省略します。実際のMFM出力にはこのプレビュー制限を適用しません。

### 絵文字取得・画像形式について

- HTTPSのMisskeyサーバーに `/api/emoji` を問い合わせ、取得した画像URLを読み込みます。ログインやアクセストークンは不要です。
- 不明な絵文字、通信エラー、CORS制限、タイムアウト、非対応の画像では「取得できませんでした」と表示します。画像を保存してファイルから読み込む方法も使えます。
- 通信先は指定したサーバーと、そのサーバーが返す画像配信先です。ブラウザー内変換なので、選択したローカル画像を外部へ送信しません。
- 入力30MB、GIFの256コマ・展開128/256MB、GIFの各辺24px・色数32、静止画の色数64といった固定制限を解除しました。PNG・JPEG・WebP・GIFなど、ブラウザーがデコードできる画像を扱います。GIFは2コマ以上で全コマ変換と静止画変換を選べます。整数として扱えるサイズ・ブラウザーのCanvas／メモリー容量・Misskeyの構文制約は残ります。GIF以外の動く画像は静止フレームとして扱います。
- MFMプレビューは本ツールが生成する `bg` / `fg` / `scale` の表示用です。フォント、折り返し、テーマ、Misskeyクライアントの設定による見え方の差があります。投稿前に実際のクライアントでも確認してください。

### 文字・画像・GIFの切り替え（試作）

GIFの全コマ変換は通常の `web/index.html` に統合済みです。GIFファイルの選択・ドロップ、任意のサーバーからのGIF絵文字取得に対応し、元の表示時間または指定周期で繰り返すMFMを生成します。コピーと `.txt` 保存に加え、各コマのMFM・表示時間をJSONで保存できます。幾何学的な再生の制約は試作と同じです。複数文字・複数画像を切り替える試作ページも引き続き利用できます。

`web/mfm-switch.html` で2〜8種類の文字、複数画像、またはGIFの全フレームを既存MFMの幾何変換で切り替えられます。例示ボタンはMisskey.ioの `petthex_meowsurprised` を取得します。GIFは画像の差分・透過・前コマの消去を反映して、完全な各フレームを個別にMFMへ変換します。元の表示時間を使うか、指定した周期で均等に表示するかを選べます。

今回のGIFは112×112、5フレーム、各80msです。各コマを縦に配置して重ねる方式へ修正し、16×16・8色の出力（8,294文字・入れ子19段）でも公式の通常の欄で全5コマの表示を確認しました。6種類の文字も試作・公式で確認済みです。プレビューは公式に合わせたフォント指定・16px表示とし、自動縮小しません。コマ数分の縦余白、切り替え時の短いワイプ、大きな負のscaleへの依存があり、一般的なGIFプレーヤーとしての互換性は保証しません。1コマ自体が表示欄より広い場合やフォント・行高が異なる場合はずれる可能性があります。仕組み・検証範囲は [MFM-SWITCH.md](MFM-SWITCH.md) に記載しています。

## Python版（従来の使い方）

# Image-to-MFM
- Q.なにこれ？ A.画像をMFMに変換するPythonプログラムです

# 使い方
1. Pythonの実行環境を用意する
  - Python 3.12 での動作を確認(他のバージョンでは未確認。古すぎなければ多分動くはず)
  - 事前に Pillow、numpy、scikit-learn をインストールしておく
    - pip install Pillow numpy scikit-learn
1. option.txtの設定
  - filename
    - 読み込む画像のファイル名を指定
    - 絶対パス または 相対パス。拡張子も含む
  - use_scale_index
    - 使用するスケールの種類の設定
    - 下記にて設定する scale の種類のうち、どれを使用するかを指定する
  - use_space_index
    - 使用するスペースの種類の設定
    - 下記にて設定する space の種類のうち、どれを使用するかを指定する
  - resize_width
    - リサイズ後の横幅(px)を指定
    - 無効な値(0)を指定すると resize_height の値を基準にアスペクト比を維持してリサイズされる
  - resize_height
    - リサイズ後の縦幅(px)を指定
    - 無効な値(0)を指定すると resize_width の値を基準にアスペクト比を維持してリサイズされる
  - smooth_repeat
    - リサイズ後の画像の色を滑らかにするための繰り返し回数
    - 指定した回数だけ画像を滑らかにする
    - 推奨値は 0 ～ 2
  - color_division
    - 色を割り算で減色するための値
    - 1.0 以上の小数値を指定。推奨値は 32.0 ～ 64.0
  - max_row_colors
    - 1行あたりの最大色数を指定
    - k-means法で色を分割する際の最大色数
    - 推奨値は 4
    - smooth_repeat、color_division との相性が悪いので、ここを設定する場合は smooth_repeat を 0、color_division を 1.0 にすることを推奨
  - color_type
    - 出力するMFMの色の種類を指定
    - 0: 6桁RGB
    - 1: 4桁RGBA
  - background_color
    - 背景色の設定
    - R, G, B, A の値を 0 ～ 255 の範囲で指定
    - color_type が 4桁RGBA の場合、アルファ値は 255 に自動で固定される
  - scale_preset
    - 使用するスケールの種類。$[scale.y= の値
    - カンマ区切りで指定 (例: 0.7, 0.185, 0.36)
  - space_preset
    - 使用するスペースの種類
    - 必ず "" で囲むこと
    - カンマ区切りで指定 (例: "　", " ")
  - max_overlap_bg_color
    - $[bg.color= をどれだけ重ねがけできるかの設定
    - MFMの仕様上、20個までしか重ねがけできないのでそれ用の設定
    - デフォルトだと $[scale.y= が含まれるので19個
    - 後から $[blur ] とか付け足したい場合はその分減らす必要がある
  - use_mfm
    - 使用するMFMの設定
    - bg 想定のプログラムだが、fg でやりたいといった場合にここを設定
    - bg または fg を指定。これ以外を指定すると勝手に bg が設定される
1. ImageToMFM.py を実行
  - 画像と同じ場所に画像と同じ名前の.txtファイルが生成される
  - その.txtファイルの中にMFMが書き込まれてる

# Tips
- リサイズの値を両方とも0にすると、元の画像のアスペクト比を保持して生成
- スペースは全角スペースが一番安定。半角スペースの場合恐らく機種ごとに大きさが違う
- ただノート用で生成しないのであれば半角スペースを使うのが一番良い
- MFMの見え方を確認したい場合は Misskey Hub のMFMお試しコーナーを使うと良い (https://misskey-hub.net/ja/tools/mfm-playground/)
